# chatformme — پیام به ما در شرایط اضطراری

یک سایت سادهٔ «پیام به ما» که می‌تونید روی سرور خودتون اجرا کنید. وقتی اینترنت بین‌الملل قطع یا محدود میشه، آدرسش رو به بقیه می‌دید تا بتونن به شما پیام بدن و شما جوابشون رو بدید.

- **هر بازدیدکننده** یه گفتگوی خصوصی با شما داره. بازدیدکننده‌ها همدیگه رو نمی‌بینن و از پیام‌های هم خبر ندارن.
- **شما (مدیرها)** یه صندوق پیام دارید که همهٔ گفتگوها توشه و می‌تونید جواب بدید. اگه چند مدیر باشید، همه همین صندوق مشترک رو می‌بینن.

**چرا برای شرایط قطعی مناسبه؟**

- **بدون هیچ وابستگی خارجی:** نه `npm install` لازم داره، نه CDN، نه فونت گوگل، نه سرویس خارجی. فقط Node.js و همین چند فایل.
- **سبک:** کل صفحه (HTML و CSS و JS) فشرده‌شده حدود ۱۸ کیلوبایته و روی اینترنت ضعیف هم سریع باز میشه.
- **مقاوم در برابر قطع و وصلی:** اگه اتصال قطع بشه خودکار دوباره وصل میشه و فقط پیام‌های جاافتاده رو می‌گیره. پیامی که ارسال نشه نگه داشته میشه و خودکار دوباره فرستاده میشه، بدون اینکه تکراری بشه.
- **فارسی و راست‌به‌چپ:** طراحی‌شده هم برای گوشی و هم برای کامپیوتر، با حالت تاریک خودکار.
- **قابل اجرا روی شبکهٔ محلی:** حتی بدون هیچ اینترنتی، روی یه لپ‌تاپ و یه مودم یا هات‌اسپات گوشی کار می‌کنه.

## امکانات

- گفتگوی خصوصی هر بازدیدکننده با شما. بازدیدکننده می‌بینه که پاسخگو آنلاینه یا نه.
- صندوق پیام مدیرها با تعداد پیام‌های نخونده و نشون دادن اینکه هر نفر الان آنلاینه یا نه
- تیک «رسید» و «خوانده شد» برای هر دو طرف
- حذف پیام (بازدیدکننده پیام‌های خودش، مدیر هر پیامی) و حذف کل یک گفتگو توسط مدیر
- رمز ورود اختیاری (فقط کسایی که رمز رو دارن می‌تونن پیام بدن)
- ذخیرهٔ امن گفتگوها روی دیسک: هر پیام همون لحظه ثبت میشه و با قطع برق یا کرش سرور از بین نمیره
- اگه بازدیدکننده از همون گوشی یا مرورگر دوباره وارد بشه، گفتگوی قبلیش سر جاشه
- محدودیت ارسال برای جلوگیری از اسپم

## اجرای سریع

پیش‌نیاز: [Node.js](https://nodejs.org) نسخهٔ ۱۶ یا بالاتر.

```bash
node server.js
```

**حتماً `ADMIN_KEY` رو تنظیم کنید.** بدون اون هیچ‌کس نمی‌تونه پیام‌ها رو بخونه و جواب بده:

```bash
ADMIN_KEY='یک-کلید-طولانی-و-مخفی' CHAT_TITLE='پیام به خانوادهٔ ما' node server.js
```

بعد آدرسی رو که در ترمینال چاپ میشه (مثلاً `http://192.168.1.5:3000`) در مرورگر باز کنید و به بقیه بدید.

اگه می‌خواید فقط کسایی که رمز رو دارن بتونن پیام بدن، `CHAT_PASSWORD` رو هم اضافه کنید:

```bash
CHAT_PASSWORD='رمز-برای-دوستان' ADMIN_KEY='یک-کلید-طولانی-و-مخفی' node server.js
```

در ویندوز (PowerShell):

```powershell
$env:CHAT_PASSWORD="رمز-برای-دوستان"; $env:ADMIN_KEY="یک-کلید-طولانی-و-مخفی"; node server.js
```

**ورود مدیر:** همون آدرس سایت رو باز کنید و اسم خودتون رو بنویسید. اگه رمز ورود تنظیم شده باشه، به‌جای رمز `ADMIN_KEY` رو وارد کنید. اگه نه، روی «ورود مدیر» بزنید و `ADMIN_KEY` رو وارد کنید. بعد از ورود، صندوق پیام رو می‌بینید.

## تنظیمات

همهٔ تنظیمات با متغیرهای محیطی انجام میشن:

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `PORT` | `3000` | پورت سرور |
| `HOST` | `0.0.0.0` | آدرسی که سرور روش گوش میده. پشت nginx بذارید `127.0.0.1` |
| `CHAT_TITLE` | `ارتباط با ما` | عنوان سایت |
| `CHAT_PASSWORD` | (خالی) | رمز ورود بازدیدکننده‌ها. اگه خالی باشه هر کسی آدرس رو داشته باشه می‌تونه پیام بده |
| `ADMIN_KEY` | (خالی) | کلید ورود مدیرها برای خوندن و جواب دادن پیام‌ها. **لازمه** و حداقل ۱۲ حرف (کوتاه‌تر باشه سرور اجرا نمیشه) |
| `DATA_DIR` | `./data` | محل ذخیرهٔ پیام‌ها و کلید امضای نشست‌ها |
| `MAX_HISTORY` | `300` | تعداد آخرین پیام‌هایی که از هر گفتگو نگه داشته میشن |
| `MAX_CONVERSATIONS` | `1000` | حداکثر تعداد گفتگوها. اگه بیشتر بشه، قدیمی‌ترین گفتگوی بی‌فعالیت پاک میشه |
| `MAX_STORAGE_MB` | `32` | حداکثر حجم همهٔ گفتگوها روی هم. اگه بیشتر بشه، قدیمی‌ترین گفتگوهای بی‌فعالیت پاک میشن |
| `TLS_CERT` و `TLS_KEY` | (خالی) | مسیر فایل‌های گواهی، برای اجرای مستقیم با HTTPS بدون nginx |
| `TRUST_PROXY` | (خالی) | اگه پشت nginx هستید بذارید `1` تا IP واقعی کاربرها خونده بشه |
| `MAX_CLIENTS` | `1000` | حداکثر تعداد اتصال هم‌زمان |
| `MAX_STREAMS_PER_IP` | `50` | حداکثر اتصال هم‌زمان از یک IP |

با عوض کردن `CHAT_PASSWORD` یا `ADMIN_KEY` همهٔ کاربرها از حساب خارج میشن و باید دوباره وارد بشن. این برای وقتیه که رمز لو رفته.

## نصب خودکار روی سرور (پیشنهادی)

با SSH به‌عنوان root وارد سرور بشید و این دو دستور رو اجرا کنید:

```bash
mkdir -p /root/chatformme-src && curl -fsSL https://github.com/mmaddeveloper/chatformme/archive/refs/heads/claude/tender-albattani-bgu8mb.tar.gz | tar -xz -C /root/chatformme-src --strip-components=1
```

```bash
bash /root/chatformme-src/deploy/install.sh
```

در پایان، آدرس سایت و کلید مدیر چاپ میشه.

نصب‌کننده برای سروری نوشته شده که برنامه‌های دیگه هم روش هست:

- به nginx، apache، برنامه‌های دیگه، بسته‌های سیستم و قوانین فعلی فایروال **دست نمی‌زنه**.
- یه پورت آزاد انتخاب می‌کنه (۳۰۰۰ یا اولین پورت آزاد بعدش) و هیچ‌وقت پورتی رو که برنامهٔ دیگه‌ای گرفته برنمی‌داره.
- اگه Node.js نسخهٔ ۱۸ به بالا روی سیستم باشه از همون استفاده می‌کنه. اگه نه، یه نسخهٔ جدا فقط برای خودش در `/opt/chatformme/node` می‌ذاره و Node.js سیستم عوض نمیشه.
- سرویس در یه محیط محدود اجرا میشه: کاربر جدا، دسترسی فقط‌خواندنی به سیستم و سقف ۳۰۰ مگابایت حافظه. پس روی چیزهای دیگهٔ سرور اثری نداره.
- اگه ufw یا firewalld فعال باشه، فقط همون یک پورت رو باز می‌کنه.
- اجرای دوباره (برای به‌روزرسانی) تنظیمات و کلید مدیر رو نگه می‌داره.
- اگه پوشهٔ `/opt/chatformme` یا سرویسی با این اسم از قبل مال برنامهٔ دیگه‌ای باشه، کاری نمی‌کنه و متوقف میشه.

تنظیمات اختیاری: `PORT=3005 CHAT_TITLE='پیام به ما' CHAT_PASSWORD='...' bash deploy/install.sh`

حذف کامل: `bash deploy/install.sh --uninstall`. پیام‌ها و تنظیمات نگه داشته میشن، مگر اینکه خودتون پاکشون کنید.

## راه‌اندازی دستی روی سرور (لینوکس)

۱. فایل‌ها رو در `/opt/chatformme` کپی کنید.

۲. فایل `/etc/chatformme.env` رو بسازید و رمزها رو در اون بنویسید:

```bash
sudo tee /etc/chatformme.env >/dev/null <<'EOF'
CHAT_TITLE=پیام به خانوادهٔ ما
CHAT_PASSWORD=رمز-برای-دوستان
ADMIN_KEY=یک-کلید-طولانی-و-مخفی
EOF
```

```bash
sudo chmod 600 /etc/chatformme.env
```

۳. سرویس systemd رو نصب کنید تا همیشه اجرا باشه و بعد از ری‌استارت سرور خودش بالا بیاد:

```bash
sudo cp /opt/chatformme/deploy/chatformme.service /etc/systemd/system/
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now chatformme
```

۴. برای HTTPS، nginx رو جلوی برنامه بذارید. نمونه‌ی تنظیمات در [`deploy/nginx.conf`](deploy/nginx.conf) هست. خط `proxy_buffering off;` برای رسیدن لحظه‌ای پیام‌ها لازمه.

## چک‌لیست قبل از قطعی اینترنت

خیلی از کارها رو **فقط قبل از قطعی** می‌شه انجام داد. همین الان آماده‌ش کنید:

- [ ] **سرور داخل کشور:** وقتی اینترنت بین‌الملل قطعه ولی شبکهٔ داخلی کار می‌کنه، فقط سرورهایی که داخل همون کشورن در دسترس می‌مونن. سرور خارجی در دسترس نخواهد بود.
- [ ] **نصب Node.js روی سرور:** در زمان قطعی، دانلود از سایت Node.js یا مخزن‌های خارجی ممکنه کار نکنه.
- [ ] **کپی کردن همین فایل‌ها روی سرور:** ممکنه GitHub هم در دسترس نباشه. یه نسخهٔ ZIP هم روی کامپیوتر خودتون نگه دارید.
- [ ] **دامنه و DNS:** از دامنه‌ای استفاده کنید که DNS اون روی سرویس داخلی باشه، یا آدرس IP سرور رو مستقیم به بقیه بدید.
- [ ] **گواهی HTTPS:** گواهی رو از قبل بگیرید. گواهی‌هایی مثل Let's Encrypt برای تمدید به سرورهای خارجی نیاز دارن و در زمان قطعی تمدید نمیشن. پس تاریخ انقضاش رو در نظر داشته باشید.
- [ ] **تست:** یه بار از اینترنت موبایل (نه وای‌فای خودتون) سایت رو باز کنید و مطمئن بشید کار می‌کنه.
- [ ] **پخش آدرس:** آدرس و رمز رو از قبل به افرادی که می‌خواید بدید، چون در زمان قطعی راه‌های ارتباطی محدوده.

## اجرا روی شبکهٔ محلی (بدون هیچ اینترنتی)

اگه هیچ اینترنتی نیست ولی چند نفر نزدیک هم هستید:

۱. لپ‌تاپ رو به یه مودم وای‌فای یا هات‌اسپات گوشی وصل کنید (خود مودم لازم نیست به اینترنت وصل باشه).

۲. اجرا کنید: `node server.js`

۳. بقیه به همون وای‌فای وصل بشن و آدرسی مثل `http://192.168.x.x:3000` رو که در ترمینال چاپ شده باز کنن.

در ویندوز اگه پیام فایروال اومد، اجازهٔ دسترسی در «شبکهٔ خصوصی» رو بدید.

## امنیت و حریم خصوصی (حتماً بخونید)

- **بازدیدکننده‌ها پیام‌های همدیگه رو نمی‌بینن.** هر کس فقط گفتگوی خودش با مدیرها رو می‌بینه. ولی **همهٔ مدیرها همهٔ گفتگوها رو می‌بینن**، پس `ADMIN_KEY` رو فقط به کسایی بدید که بهشون اعتماد دارید.
- **پیام‌ها روی سرور به‌صورت متن ساده ذخیره میشن** (در پوشهٔ `data`). هر کسی به سرور دسترسی داشته باشه (از جمله شرکت میزبان) می‌تونه اون‌ها رو بخونه. این برنامه رمزنگاری سرتاسری (end-to-end) نداره.
- **بدون HTTPS** پیام‌ها و رمز ورود در مسیر شبکه قابل شنود هستن. اگه می‌تونید حتماً از HTTPS استفاده کنید.
- برای اطلاعات خیلی حساس از این سایت استفاده نکنید.
- `CHAT_PASSWORD` و `ADMIN_KEY` رو حتماً تنظیم کنید و `ADMIN_KEY` رو به کسی ندید.
- برای حذف یک گفتگو، مدیر گفتگو رو باز می‌کنه و دکمهٔ سطل زباله رو بالای صفحه می‌زنه. برای پاک کردن همهٔ گفتگوها: سرور رو متوقف کنید، فایل‌های `snapshot.json` و `journal.log` رو از پوشهٔ `data` پاک کنید و دوباره اجرا کنید.
- محافظت‌های داخلی برنامه:
  - **ورود:** بعد از ۱۰ رمز اشتباه از یک IP، اون IP پونزده دقیقه نمی‌تونه وارد بشه. تلاش‌های ناموفق در لاگ سرور ثبت میشن. نشست مدیر بعد از ۷ روز و نشست بازدیدکننده بعد از ۳۰ روز منقضی میشه.
  - **نشست:** اتصال زندهٔ پیام‌ها با یه کوکی HttpOnly انجام میشه، نه توکن داخل آدرس. پس توکن توی لاگ‌های سرور یا nginx نمی‌مونه و جاوااسکریپت هم بهش دسترسی نداره.
  - **پرشدن دیسک و حافظه:** محدودیت تعداد پیام، تعداد گفتگوی جدید (از هر IP و در کل)، حجم هر گفتگو و حجم کل.
  - **فایل‌ها:** پیام‌ها و کلیدها فقط برای کاربر خود سرور قابل خوندنن (پوشه با دسترسی 700 و فایل‌ها 600)، که روی سرور مشترک مهمه.
  - **مرورگر:** جلوگیری از XSS (متن پیام‌ها هیچ‌وقت به‌صورت HTML اجرا نمیشه)، سیاست امنیت محتوا (CSP) که اجازهٔ بارگذاری هیچ منبع خارجی رو نمیده، و هدرهای امنیتی دیگه (COOP، CORP، Permissions-Policy، و HSTS وقتی HTTPS فعاله).
  - **اتصال‌های کند یا نیمه‌باز** نمی‌تونن سرور رو مشغول نگه دارن.

## ذخیره‌سازی پیام‌ها

پیام‌ها در پوشهٔ داده (`DATA_DIR`) ذخیره میشن:

- `journal.log`: هر تغییر (پیام جدید، حذف، خوانده شدن و...) یک خط. همون لحظه نوشته میشه و ظرف کمتر از یک ثانیه روی دیسک قطعی میشه.
- `snapshot.json`: وضعیت کامل در یک لحظه. وقتی `journal.log` بزرگ میشه، توی اون ادغام میشه.
- `secret.key`: کلید امضای نشست‌ها. اگه پاکش کنید همه از حساب خارج میشن.

اگه سرور وسط نوشتن قطع بشه، خط نیمه‌کاره موقع اجرای بعدی تشخیص داده و کنار گذاشته میشه. فایل `conversations.json` نسخه‌های قبلی هم خودکار به این قالب منتقل میشه. برای پشتیبان‌گیری کافیه کل پوشهٔ داده رو کپی کنید.

دو سرور نمی‌تونن هم‌زمان از یک پوشهٔ داده استفاده کنن؛ دومی با پیام خطا متوقف میشه.

## فونت (اختیاری)

سایت به‌طور پیش‌فرض از فونت خود دستگاه استفاده می‌کنه (Segoe UI و Tahoma در ویندوز، فونت سیستم در اندروید و آیفون) و هیچ فونتی از اینترنت دانلود نمی‌کنه.

برای ظاهر یکدست‌تر روی همهٔ دستگاه‌ها می‌تونید فونت آزاد [وزیرمتن](https://github.com/rastikerdar/vazirmatn) رو کنار سایت بذارید:

۱. فایل‌های `woff2` رو از بستهٔ وزیرمتن بردارید. هر کدوم از این‌ها کافیه:
   - `Vazirmatn[wght].woff2` (یک فایل برای همهٔ وزن‌ها)
   - یا `Vazirmatn-Regular.woff2` و `Vazirmatn-Bold.woff2`

۲. فایل‌ها رو در پوشهٔ `public/fonts/` بذارید و سرور رو دوباره اجرا کنید. تنظیمات فونت خودکار اضافه میشه.

فونت از سرور خودتون بارگذاری میشه، پس در زمان قطعی هم کار می‌کنه.

```
server.js            سرور (فقط با ماژول‌های داخلی Node.js)

public/index.html    صفحهٔ سایت

public/fonts/        (اختیاری) فایل‌های فونت وزیرمتن
public/app.js        منطق سمت مرورگر
deploy/              نمونهٔ تنظیمات systemd و nginx
test/smoke.js        تست خودکار سایت
test/storage.js      تست ذخیره‌سازی (کرش، قطع برق، انتقال داده)
.claude/skills/      مهارت‌های طراحی رابط کاربری برای Claude Code (از emilkowalski/skills)
```
